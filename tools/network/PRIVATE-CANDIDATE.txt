Private async Squid candidate — 2026-10-02

Status: Private candidate. NOT installed by setup.sh or enabled by default.
A private guest clone must contain the two root-owned executable scripts and
updated config-agent.py, and boot with bromure.experimental_async_squid=1.
Do not add Chrome proxy bypasses for acceptance. Production and externally
configured proxy branches retain their existing commands without this opt-in.

Private-image installation (root, OFFLINE clone or before config-agent starts):
  install -o root -g root -m 0755 async-squid-gateway.py /usr/local/bin/
  install -o root -g root -m 0755 async-squid-launch.py /usr/local/bin/
  install -o root -g root -m 0755 config-agent.py /usr/local/bin/

Requires existing proxy/nobody accounts, Python 3.9+, iptables and ip6tables
with owner/NAT/REDIRECT kernel support and Squid. Missing
requirements fail closed; no direct or legacy fallback after an opted-in failure.
Use a fresh VM. Never start alongside the legacy proxychains Squid process.
Logs: /tmp/bromure/resilient-launch.0.log; supervisor emits
BROMURE_ASYNC_SQUID_ACTIVE with verified Squid/gateway PIDs and distinct UIDs.

Routing:
- Squid retains DNS resolution, filtering, ACLs and cache_peer configuration.
- ALL Squid-UID outbound TCP (IPv4, IPv6, including loopback) is redirected.
- Original numeric IP/port goes ONLY to existing routing-socks on localhost40001.
- Gateway runs as nobody; Squid is launched as proxy before exec, without preload.
- IPv6 listener is omitted ONLY when all/default/lo/every interface disable_ipv6
  values are verified1. Both IPv4 and IPv6 UID NAT rules are still mandatory.
  Later policy change remains redirected (no listener, no egress) and supervisor
  stops Squid; no IPv6 sysctl is enabled by this candidate.
- Other UIDs are unaffected. No direct gateway destination injection is accepted.
- IPv6 scoped/link-local addresses fail closed: SOCKS cannot convey scope IDs.
- Maximum256 active connections, 30s connect handshake, 64KiB relay buffers with
  drain backpressure, 24h connection lifetime. Excess connections are closed.
- Supervisor stops Squid before removing owned rules. Worker failure stops both.
  SIGKILL/power loss may leave rules within that guest; stale chains are refused,
  never blindly flushed. A fresh private boot is the recovery path.

Counters: active/peakActive, accepted SOCKS connections, rejectedCapacity,
completed relays, failed by originalDestination/connect/relay phase, fixed
error categories, bounded errno histogram, SOCKS reply codes, EOFs and bytes
READ from Squid/router. Read bytes are not proof of delivery or decryption.
Connection closure after a valid full body can still raise an EOF/shutdown
error; do not equate every relay failure with failed HTTPS handshakes. Compare
counter deltas at the exact browser error time and corroborate with the
layered probe/cache.log. Supplement with process FD/thread counts (no argv or
environment dump) to see the production routing-socks thread pool as well.
