# Appendix — Shortcuts, Files, Ports & Environment

This appendix collects the concrete facts scattered through the rest of the manual into reference tables: keyboard shortcuts, on-disk locations, network ports, environment variables and defaults, and a guest-VM cheat sheet. Everything here is keyed to the shipping build (version 5.0.0, bundle ID `io.bromure.agentic-coding`, app binary `bromure-ac`). For the commands that read and write these, see [CLI, API & MCP](16-automation-cli.mdx); for what gets created at install time, see [Installation & First Run](02-installation.mdx).

Placeholders used below: `<uuid>` is a machine's (workspace's) identifier, `<id>` a cluster's, registry's or run's identifier, `<version>` a pinned tool version, `<org>--<name>` a model repository, and `<host-UUID>` a saved remote host.

Everything the app owns lives under one support directory, plus a handful of files outside it and a few Keychain items. A path ending in `/` is a directory.

## Network ports and subnets

### TCP and loopback ports

Bromure Agentic Coding opens no fixed inbound ports by default. The two optional services below are off until you enable them; the rest are loopback-only and either dynamic or internal.

| Port | Purpose | Bound where |
|---|---|---|
| `9223` (default) | Automation HTTP API and `bromure-ac mcp` backend. Off by default (`automation.enabled`); one off from the browser product's 9222 so both apps can run side by side. Serves `GET /health`. | `127.0.0.1` (configurable via `automation.bindAddress`; non-loopback binds are unauthenticated and warned against). |
| `2222` (default) | Optional SSH remote-access front door. Disabled by default; configurable to any port ≥ 1024. | `0.0.0.0` by default (configurable via `remoteAccess.bindAddress`). |
| `28500`–`28599` | MCP OAuth callback listener (`http://127.0.0.1:<port>/callback`). | `127.0.0.1`. |
| dynamic | On-device inference engine, allocated at first spawn to avoid colliding with Ollama/LM Studio on 11434. | `127.0.0.1` (never `0.0.0.0`). |
| dynamic | Local-inference tool-call repair proxy. | `127.0.0.1`. |
| ephemeral | Per-remote-host SOCKS5 forwarder used by the rich client's browser pane. | Bound `0.0.0.0` but peer-filtered to loopback plus `192.168.127.x`. |

Two loopback endpoints exist *inside* the guest, not on the Mac: `127.0.0.1:65534` (the in-VM HTTP(S) proxy every shell exports as `HTTPS_PROXY`) and `127.0.0.1:11434` (where the on-host inference engine appears, over vsock).

Installation itself opens no TCP ports; the base-image build's package proxy binds an ephemeral localhost port per build.

### Virtual-network subnets

| Subnet | Purpose |
|---|---|
| A random `/24` in `172.16.0.0/12` | The machines' network on fresh installs (gateway `.1`, DHCP pool `.2`–`.254`). Chosen once per install, avoiding Docker's usual `172.17`–`172.20` and any range the Mac is on. View, turn off or re-randomize it under **Preferences › Resources › Workspace subnet**. |
| `192.168.64.0/24` | The machines' network on installs that turned the private subnet off. Auto-relocated if the Mac's LAN already uses it. |
| `192.168.65.0/24`–`192.168.126.0/24` | Range Bromure Web instances relocate into, keeping AC and Web from colliding. |
| `192.168.127.0/24` | The rich client's pinned local browser-VM subnet (gateway `.127.1`). |
| `10.98.<unit>.0/30` | Point-to-point link networks used by the privileged utun tunnel daemon. |

IPv6 is not routed: recent base images disable it inside the guest, and `apt` runs over IPv4 only.

### Host↔guest vsock ports

| vsock port | Bridge |
|---|---|
| 5800 | Shell-exec agent — powers `vm exec`, the control-socket exec route, and the Files pane. |
| 5010 | Loopback OAuth-callback relay (delivers OAuth redirects back into in-VM CLIs). |
| 5830 | Browser MCP server. |
| 5831 | Task-board MCP server (coding tasks only). |
| 5832 | Plan stream (coding-task planning). |
| 5833 | Automations MCP server. |
| 5834 | Infrastructure MCP server. |
| 5835 | Delegation MCP server. |
| 5836 | Switchboard MCP server (the Switchboard session only). |
| 8443 | HTTPS MITM proxy — the guest's egress. |
| 8444 | ssh-agent bridge (backs `SSH_AUTH_SOCK`). |
| 8445 | AWS `credential_process` helper. |
| 8446 | Claude subscription-token agent, and the on-host inference bridge (guest `127.0.0.1:11434`). |
| 8447 | Codex/ChatGPT subscription-token agent. |
| 5000 | Browser-VM config agent (host→guest JSON config at claim). |
| 5100 | Browser-VM file transfer bridge. |
| 5200 | Browser-VM Chrome DevTools Protocol bridge (screenshots, eval). |
| 5300 / 5400 | Browser-VM link-sender / webcam. |
| 5810 | Browser-VM native-tabs bridge. |
| 5900 | Browser-VM network-trace bridge. |

## Guest-VM cheat sheet

Inside a running machine you are `ubuntu`, an ordinary user (`sudo`-capable) whose home is `/home/ubuntu`. The host wires up mounts and environment so package managers, agents, and Git work without any in-guest setup. See [Concepts & Architecture](04-concepts.mdx) for the mechanics.

### Mount points and paths

| Path | What it is |
|---|---|
| `/home/ubuntu` | Your home — the ext4 `home.img` (or a shared folder on machines not yet upgraded). |
| `/mnt/bromure-meta` | Read-only per-launch config share: `api_key.env`, `proxy.env`, the CA cert, guest helpers, MCP shims and configs, hostname/MTU hints. |
| `/mnt/bromure-meta/bromure-*-mcp.py` | The built-in MCP servers' stdio↔vsock shims (browser, task, automations, infra, delegation, switchboard). |
| `/mnt/bromure-outbox` | Writable guest→host event share. |
| `/mnt/bromure-share-N` | Shared project folders (up to 8), also symlinked into your home as `~/<basename>`. |
| `~/.bromure/inbox/<id>/` | Files another agent sent this session with a delegation or request. |
| `~/.bromure/switchboard` | The Switchboard's folder; its `CLAUDE.md` is the Switchboard's brief. |
| `~/.bromure/rooms/<slug>` | A room Switchboard's folder. |
| `~/.bromure/pastes/` | Files pasted or dropped into a machine's terminal (auto-cleaned after 7 days). |

### Environment set by the host

| Variable | Value / effect |
|---|---|
| `http_proxy`, `https_proxy`, `HTTPS_PROXY` | `http://127.0.0.1:65534` — the in-VM bridge that carries all guest HTTPS to the host MITM proxy. |
| `NO_PROXY` | `localhost,127.0.0.1,::1`. |
| `SSH_AUTH_SOCK` | `/tmp/bromure-agent.sock` — bridged over vsock to the host ssh-agent (only per-machine and explicitly imported keys are reachable; your macOS login agent is never exposed). |
| CA bundle variables | The re-signing root CA is trusted through the standard bundle variables for node, python, go, rust, curl, deno, and the AWS SDK. |
| Agent API keys | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `XAI_API_KEY`, `GH_TOKEN`, `GITLAB_TOKEN`, `DIGITALOCEAN_ACCESS_TOKEN`, `LINEAR_API_KEY`, `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN`, the AWS variables, and any database or custom variables — all **stand-in** values; the host swaps in the real secret on the wire. |
| On-device and custom-server models | Claude Code sees `ANTHROPIC_BASE_URL=https://bromure.llm`, a per-VM `ANTHROPIC_AUTH_TOKEN`, the real model id in `ANTHROPIC_MODEL` and its size aliases, and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`. |
| OpenRouter | Claude Code sees `ANTHROPIC_BASE_URL=https://openrouter.ai/api`, a stand-in `ANTHROPIC_AUTH_TOKEN`, an empty `ANTHROPIC_API_KEY`, and the chosen model ids per size. |
| Amazon Bedrock | Claude Code sees `CLAUDE_CODE_USE_BEDROCK=1`, `AWS_REGION`, and either a stand-in `AWS_BEARER_TOKEN_BEDROCK` (Bedrock API key) or `AWS_PROFILE=default` (AWS credentials). |
| `KIMI_CODE_OAUTH_HOST`, `KIMI_CODE_BASE_URL` | With a Kimi subscription: point Kimi Code at Kimi's international service. |
| `BROMURE_REGISTRY` | The address of a Bromure registry this machine has access to. |

> **Warning:** Every credential the guest can read is a decoy. A stand-in token scoped to one host that appears in a request bound for a different host is the signature of exfiltration and trips [compromise detection](08-credentials.mdx) — it never authenticates anything.
